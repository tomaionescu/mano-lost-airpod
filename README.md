# Mano & the Lost AirPod

A third-person story game set on the EPITA campus in Le Kremlin-Bicêtre, made in Godot 4.7. It follows one
evening, from 17:42 to past midnight, in which Mano looks for his missing AirPod and keeps running into his friends.

## What it is

Mano wakes up after the algo lecture in Amphi 4 with one AirPod, a phone about to die and a promise he does not
remember making. The other AirPod keeps moving: from Karim to the lost & found, then to a note signed "C.". Following
it takes him through the Voltaire building, the cafeteria, cour Pasteur, the Under and rue Pasteur while the light
goes from golden hour to night.

The story is a short cold open and five chapters: "Mono", "Lost & Found", "Blue Hour", "Sauce Samouraï" and
"Stereo". The main path is an estimated 50 minutes. Mano and the seven friends he meets are real people who agreed
to appear; the other characters are fictional.

Along the way the player gets:

- seven minigames: the moulinette (a day and a night variant), babyfoot (1v1 or 2v2), the coffee machine, the lost
  & found box, Joaquin's kebab orders, a search by sound in the Under, and "1, 2, 3, ACU!";
- Mano's phone, usable from chapter 3: message threads with replies, a finder for the AirPod, and the songs heard
  so far;
- a journal with six tabs (today, people, film, ducks, moments, on the side) and a campus map drawn from the
  level's own footprints;
- optional things to find: twelve golden ducks, ten photo spots for Ishita's disposable camera, six places to sit
  down with a song, four side stories, and conversations overheard in passing;
- photo mode, a wardrobe, chapter select, and autosave.

## Technical highlights

- The story is data. Dialogue lives in 16 plain-text `.dlg` files (213 cues) written in a small format with
  branches, conditions, jumps, random groups and 34 story commands, parsed and compiled on demand by
  [`dialogue_data.gd`](scripts/story/dialogue_data.gd). [`story_commands.gd`](scripts/story/story_commands.gd)
  declares every command and its argument types in one table, and the validator
  ([`validate_dialogue.gd`](tests/validate_dialogue.gd)) reads that table to reject unknown commands, missing
  cues, unknown speakers, undeclared flags, conditions that do not parse and references to places that do not exist.
- Chapters are data too. [`data/chapters.json`](data/chapters.json) holds each chapter's clock, light, staging,
  triggers and to-do list; [`scripts/story/chapters.gd`](scripts/story/chapters.gd) derives the current objective
  from the story flags alone, so the game and the tests run the same rules. The 115 flags are declared with their
  defaults in [`data/flags.json`](data/flags.json).
- Saves are versioned and written atomically: a temporary file, then a rename that keeps the previous save as a
  backup, which is read if the main file is missing or damaged. Older saves are migrated on load
  ([`scripts/core/game_state.gd`](scripts/core/game_state.gd)).
- A headless test suite ([`tests/`](tests)) compiles every script, validates the story data, and walks the whole
  quest without a level, taking every answer to every question and losing each minigame once. Scripted playthroughs
  ([`scripts/dev/autotest.gd`](scripts/dev/autotest.gd)) then drive the real game and save screenshots. Test runs
  use their own save paths.
- Characters come out of a Python and Blender pipeline ([`tools/blender/build_human.py`](tools/blender/build_human.py)).
  MakeHuman bodies get a face fitted to photos: MediaPipe landmarks, a camera pose from solvePnP, and displacements
  spread over the head with a radial basis function ([`face_fit.py`](tools/blender/face_fit.py),
  [`face_solve.py`](tools/py/face_solve.py)). Hair is grown as strand cards along a flow field
  ([`hair_gen.py`](tools/blender/hair_gen.py)), and motion capture is retargeted with two-bone IK and foot
  locking ([`retarget.py`](tools/blender/retarget.py)). Six outfits wrap the rigged body onto an AI-generated
  3D model of the outfit, keeping the skeleton and the face shapes ([`scan_wrap.py`](tools/blender/scan_wrap.py)). See
  [docs/PIPELINE.md](docs/PIPELINE.md).
- The campus is generated by Blender scripts ([`tools/blender/build_campus.py`](tools/blender/build_campus.py)) on
  the real building footprints from the French cadastre and IGN data, converted to game coordinates. The method
  and the measurements are in [docs/CAMPUS_LAYOUT.md](docs/CAMPUS_LAYOUT.md).
- Rendering uses Godot's Forward+ renderer with SDFGI, SSAO and SSIL, volumetric fog and AgX tonemapping. Six
  time-of-day presets use the sun positions of 15 October 2026, each with its own grading LUT
  ([`scripts/level/world_env.gd`](scripts/level/world_env.gd)). On HiDPI screens the 3D world renders in a
  separate viewport at one pixel per point with FSR2 upscaling, while the UI draws at native resolution
  ([`scripts/level/world_view.gd`](scripts/level/world_view.gd)).

## Run it

The models, textures, audio and video are stored with Git LFS, about 2 GB in all. Install it before cloning:

```sh
git lfs install
git clone <this repository's URL>
```

The game needs [Godot 4.7.2](https://godotengine.org/download), standard build. On macOS, double-click
`Play Mano.command`: it expects Godot at `~/Applications/godot/Godot.app` and says so if it is not there. Anywhere
else, open `project.godot` in the Godot editor and run the project. The first launch imports the assets, which
takes a few minutes; later launches start in seconds. Development and testing have been on macOS only.

Progress saves on its own every 30 seconds, after each conversation and at each chapter card. Continue is on the
title screen, next to a chapter select for the chapters already reached. Quality presets are under Esc, Settings:
High, the default, uses real-time global illumination; Medium turns it off.

## Controls

| Action | Keyboard / mouse | Controller |
|---|---|---|
| Move | WASD / ZQSD / arrows | Left stick |
| Look | Mouse | Right stick |
| Jog | Shift | L3 |
| Talk / use | E, Space | A |
| Journal (hold: what's next) | Tab, J | View |
| Phone (from chapter 3) | Q (A on AZERTY) | D-pad down |
| Campus map | M (`,` on AZERTY) | Y |
| Fits (wardrobe) | F | X |
| Photo mode | P (C saves a picture to Pictures, or puts a framed spot on Ishita's film) | D-pad up |
| Pause & settings | Esc | Menu |

## Tests

```sh
GODOT="$HOME/Applications/godot/Godot.app/Contents/MacOS/Godot"
"$GODOT" --headless --path . --import                                              # once, after cloning
"$GODOT" --headless --path . res://tests/test_runner.tscn                          # all tests; exits 1 on a failure
"$GODOT" --headless --path . res://tests/test_runner.tscn -- only=validate,quest   # some tests only
```

| Test | What it checks |
|---|---|
| `compile` | every GDScript in `scripts/` and `tests/` loads and compiles |
| `validate` | the dialogue files and the JSON data are consistent with each other |
| `port` | the lines and objectives recorded in `tests/fixtures/` are still present in the data |
| `quest` | the story plays from the cold open to the ending, once on the main path and once through every branch |
| `saves` | round trips, migration of old saves, recovery from a truncated file or an interrupted write |
| `map` | the campus plan loads and no two map labels overlap |

Three more headless checks cover the interface: `res://scenes/dev/line_check.tscn` (every subtitle fits two
lines in the real font), `hud_check.tscn` and `ui_check.tscn` in the same folder.

The scripted playthroughs need a window. `"$GODOT" --path . -- autotest=story` plays the whole story and writes
screenshots to `shots/`; add `chapter=3` to start at a chapter. The other plans are listed at the top of
[`scripts/dev/autotest.gd`](scripts/dev/autotest.gd).
